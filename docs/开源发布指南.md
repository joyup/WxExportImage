# 开源和 Windows 发布

现有开发仓库的旧提交含个人群名、联系人表和真实会话信息。
`.gitignore`、取消跟踪或新的删除提交都不会清除历史。不要直接将这个仓库的 `.git` push 到公开 GitHub。
本机旧数据保留用于兼容；公开版本使用白名单源码快照。

```powershell
.venv/Scripts/python.exe tools/prepare_public_source.py --directory dist/github-source
```

结果为独立源码目录 `dist/github-source/`、`dist/wechat-photo-export-source.zip` 和对应 `.sha256` 校验文件，
源码目录及 ZIP 都附逐文件 SHA-256 清单。只含桌面应用、公共 CLI、项目技能入口、人工构造的测试、
构建配置和开源文档，没有旧 `.git`、`data`、本地兼容文档、编号脚本或照片。
`--directory` 目标须不存在或为空，已有内容会保留并拒绝生成；再次准备版本时使用新的空目录。
审阅后，从独立源码目录初始化新仓库。以下 GitHub URL 是占位示例，须替换为自己的仓库：

```powershell
Set-Location dist/github-source
git init -b main
git add .
git diff --cached --stat
git commit -m "Initial public source"
git remote add origin "https://github.com/示例用户名/示例仓库.git"
git push -u origin main
```

不要复制旧 `.git` 或个人数据。发布前检查文档、源码和压缩包，确认没有真实账号、会话标识、
聊天内容、密钥、个人目录路径或本机数据统计。占位示例应明确标注，第三方许可和来源署名保留原文。
快照隔离旧开发历史和本地数据，不代替代码与依赖审阅；已解压的旧发行包不会随文档修改自动更新。

项目自有代码采用 MIT；第三方组件许可见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)。
发行前启用 GitHub Private vulnerability reporting、保护主分支、要求 CI，通过 issue 模板收集脱敏信息。
测试及构建任务只有读取仓库权限；标签触发的 Release 任务单独获取发布所需的写入权限。
Actions 固定到 commit，不使用个人微信样本或上传密钥。
构建输入版本在 `requirements-desktop.lock` 固定；这是版本锁，不是带下载哈希的供应链完整性锁。
正式发布还应审阅 wheel 来源及依赖更新，记录构建输入哈希。
Qt 许可资源在 `licenses/`，来源与摘要记录于清单，打包前会核对；依赖版本升级须同步更新资源。

Windows 构建：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-desktop.lock
.venv/Scripts/python.exe -m pip install --no-build-isolation -e .
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe tools/build_windows.py
```

输出为 `dist/WeChatPhotoExport/` 目录版及 `dist/WeChatPhotoExport-windows-x64.zip`，
同时生成 `SHA256SUMS.txt`。构建脚本收集许可证及依赖版本，冻结程序自检失败时不生成分发 ZIP。
目录包不含微信 DLL；Qt 动态库保留为可替换文件。请完整分发目录包及许可证。

当前构建未进行代码签名，不能标为已签名或保证无系统提示。正式发布前使用项目维护者的
签名证书签署 EXE、验证签名，再重新生成 ZIP 与校验值；CI 中证书只用于受信发布流程。
普通 `main` 推送生成 Actions Artifact；推送 `v*` 标签时，测试和冻结程序自检通过后，
CI 自动将 Windows ZIP、`SHA256SUMS.txt`、干净源码 ZIP 及其 `.sha256` 文件发布到 GitHub Release。
当前自动发布均标记为未签名预览版。发布任务使用内置 `GITHUB_TOKEN`，无需额外保存个人访问令牌。

版本标签必须等于 `v` 加 `pyproject.toml` 中的版本，且与 `src/wechat_photo_export/__init__.py` 一致。
从干净公开仓库执行以下命令；示例为当前版本，后续版本先更新两个版本声明并提交：

```powershell
git tag v0.2.0
git push origin v0.2.0
```

发布前会校验两个 ZIP 的摘要及版本。文件先上传到草稿，全部到齐后才公开；失败时可重跑同一标签的
workflow 继续草稿。已公开 Release 的附件保持原样，新版本使用新标签。

发布说明注明应用版本、Python/Qt 版本、系统和微信实测范围、未签名状态及已知 WXGF 限制。
在无 Python 的干净机器上验收后再标为稳定版；现阶段标为预览版。
安装程序、自动更新和 macOS 后端属于后续范围。
